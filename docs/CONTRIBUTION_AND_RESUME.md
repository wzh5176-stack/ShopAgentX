## 实际协作方式

| 部分 | 本项目中的工作方式 |
| --- | --- |
| 需求/路线 | 学习者确定简历项目目标、Java/Python协作、前端交给AI辅助、多实例与Cluster演练；根据反馈调整顺序 |
| Java与Python学习 | 采用逐文件/完整代码/请求路径讲解后手动实现，隔相关步骤集中检查；部分集成和报错修复曾明确交由AI完成 |
| 前端 | 学习者选择跳糖选物等视觉方向，AI辅助实现页面与接口接线，其他设计保留 |
| 部署与实验 | 本阶段学习者按教学手动执行Linux/PowerShell命令，AI做只读核对与说明；历史曾短暂授权自动草稿，未据此认定自动部署完成 |
| 验收 | 有历史受控模型技术检查、真实模型演示、学习者网页/故障操作反馈、AI独立只读结果；每份记录分别说明来源 |
| 文档 | AI协助整理设计、教学、验收与本轮交付资料，学习者仍需按实际掌握程度复述 |

不写“全部独立原创”“完全复刻原项目所有能力”或“生产级高可用已经上线”。真实职责比技术名词数量更有说服力。

## 简历项目介绍草稿

**ShopAgent：商品选购与AI导购系统（学习实践项目）**

技术：Java17、Spring Boot、Spring Security、MyBatis-Plus、MySQL、Redis/Spring Session、Python/FastAPI、DeepSeek API、BGE/FAISS、Docker Compose、Nginx。

- 构建Java业务服务与Python AI服务协作的商品选购流程，支持真实商品查询、预算条件、多轮流式导购和会话历史；通过本地向量检索与引用展示实现资料问答。
- 实现购物车待确认操作单与状态流转，结合用户归属校验、有效期、数量基线、短事务与重复请求处理，将自然语言识别和实际业务执行衔接起来。
- 完成Linux容器化部署、Nginx双Java实例和Redis共享登录会话，演练单实例停止恢复；另完成独立RedisCluster三主三从故障提升及MySQL备份隔离恢复验证。

以上是可编辑草稿。投递时保留能结合代码解释、能自己演示的条目，前端AI辅助和参考来源按实际情况说明。不列LangGraph、JWT、SpringCloud治理、订单支付等未实现能力。

## 指标怎么用

本轮2vCPU/4GiB配置VM、小数据商品分页接口，预热5次后30次单并发请求：30/30成功、平均9.89ms、P9514.94ms。101.08次/s是该次执行速率，不能写成最大QPS或高并发能力；没有A/B对照，不能写“双实例提速X%”。完整条件与来源见[实测报告](PRODUCT_BASELINE_REPORT.md)。

可以在面试中用这一组数据说明自己有测量和边界意识；它不需要成为简历最醒目的性能卖点。Cluster故障窗口与SQL恢复耗时未测，不填秒数。
