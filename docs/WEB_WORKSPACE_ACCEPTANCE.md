## 现在怎么体验

正常地址：http://127.0.0.1:8888/shopagent/play.html 。可以注册自己的账号，登录后读取本人对话与购物车。

1. 在“聊选购”输入预算、品类、用途。网页调用本人会话的 `/messages/stream`，先逐段显示文字，收到服务器提交完成的 `done` 后才把消息作为已保存记录展示。
2. 在推荐商品上点“设置购物车”，会带上该份推荐的真实消息编号，并填入“把第1款在购物车中的数量设为1”这样的草稿。可以修改最终数量，再提交。
3. “改购物车”通过 `/turns` 识别操作。生成卡片时尚未改购物车；点确认才执行，取消则保留原数量。这里的数量是最终总量，不是额外增加几件。
4. 右上角购物车支持直接改最终数量、移除、查看合计。生成操作后如果又手动改了数量，旧操作确认会显示“数量已变化”，避免覆盖刚改的值。
5. 刷新页面会恢复本标签页当前账号选择的会话。历史卡片按操作编号重新读取状态，不把历史文本中的“请确认”误当当前仍待确认。

当前终端只确认模型密钥是否存在，没有读取其值，结果为不存在。因此正常 Java 服务已启动，Python 8000 留空，需运行用户原来带密钥的 PyCharm Uvicorn 配置才能体验真实模型回答。没有把受控模型测试服务留在正常地址。

## 一次请求怎样走

网页输入 → Java 会话接口 → Python 理解需求/生成回答 → Java 复核真实商品并保存消息 → 网页更新。

购物车请求多一步：网页带真实推荐消息编号 → Java 读取该份推荐 → Python 提取商品位置和最终数量 → Java 复核并保存待确认操作及关联消息 → 用户确认 → Java 原子修改购物车与操作状态。

`workspace.js` 中的 `api()` 负责同源 Cookie、每次写入前获取 CSRF、读取 JSON 和错误信息。`X-Requested-With: XMLHttpRequest` 只是告诉后端以网页方式反馈401，不能替代用户名密码，也不能绕过权限。

`streamGuide()` 读取 SSE，`delta` 只是生成预览，`done` 才是已提交消息。停止显示、断线都可能发生在服务器提交附近，所以页面保留输入并提示刷新记录核对，不自动重发写入。

`loadHistory()` 读保存消息，`loadAction()` 另读操作最新状态。`decideAction()` 同步锁住按钮避免双击提交；409使用后端返回的当前状态。账号退出或401会清除私人 DOM，旧账号的迟到响应有身份与会话检查。
